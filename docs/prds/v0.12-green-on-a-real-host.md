# v0.12 — green on a real host

## Goal

Every suite this project has ever recorded as green was green **because of where
it ran**, not only because the code was right. Two environments have been
measured — a job container, and `scripts/host_like_pytest.sh` inside a job
container — and they share a blind spot. On an ordinary developer host (a
populated `~/.pi`, a `pip install --user -e .` layout) seven tests failed at
`129e677`, the last commit of v0.11, whose own message is *"re-verify report and
docs guards at the true final sha"*. Two more guards were red there too, one of
them because a *report* cited a directory that only exists on the machine that
generated it.

None of that is a coincidence of one afternoon. It is one defect shape appearing
in three places: **code that reads the ambient `$HOME`**, **tests that inherit
it**, and **guards whose answer depends on the filesystem they happen to run
against**. #83 has stayed open across two waves for exactly this reason.

v0.12 closes that shape. When it ships, "the suite is green" means the same
thing on a host, in a container, and in a clone — and the project can *prove*
it, because it will have run in an environment that is able to fail.

Five issues: **#83** (HIGH, two waves open), **#85**, **#84**, **#86**, **#87**.

## Read this before anything else

Three things about your own situation, all verifiable:

1. **Your container is not a developer host.** `container/Dockerfile:42` installs
   ralphd system-wide (`pip install --no-cache-dir /opt/ralphd`), so `$HOME` never
   affects whether `ralphd` imports. On a `--user` editable install it does.
   Every test you write about this class has to be checkable *from here*, which
   means constructing the hostile layout deliberately rather than hoping to
   inherit it.
2. **`scripts/host_like_pytest.sh` cannot fail the way a host fails.** It runs
   with a fresh **empty** `$HOME`. An empty home has no `~/.pi/agent/models.json`,
   and `check_hat_routes` documents an empty provider list as "this profile
   hasn't declared anything yet" and skips the whole check. So the script's green
   is silent about the very thing it is quoted for.
3. **The evidence is already written down.** #84 lists the seven failures and
   their two mechanisms; #85 names the ambient read; #86 names the guard; #87
   quotes the event. Read the issues before re-deriving any of it.

# The requirements

## Half 1 — the ambient-`$HOME` class, closed (#83, #85, #84)

### A — the test harness isolates `HOME` by default

`EngineProc` (`tests/test_e2e.py`) and `LiveRun` (`tests/conftest.py`) build a
child's environment from `{**os.environ, **(stub_env or {})}`. A module that does
not override `HOME` therefore spawns a child engine whose ordinary,
correct-for-itself startup wipes `~/.pi/agent/skills/` — the residual #83 stays
open for, reproduced by `tests/test_skills_placement_ambient_home_loss.py`.

Invert the default: **both spawn into an isolated `HOME` unless the test asks for
inheritance**, through one explicit, named opt-in (a keyword argument or a
sentinel in `stub_env` — your choice, but exactly one spelling, and greppable).
Every module that genuinely needs the ambient home says so at its call site.

This flips `test_skills_placement_ambient_home_loss.py`'s assertion. That is the
point: rewrite it to assert the loss **cannot** happen, keep the mechanism it
documents in its docstring, and say in the commit message that the reproducer
became a regression test.

**Acceptance:** a suite run under an operator-like `$HOME` containing a placed
skill leaves that placement intact, proven by a test that places a skill, runs a
real subset in the same home, and re-checks discoverability by the agent's own
rule (the shape `test_skills_discoverability_survives_suite.py` already uses,
widened to modules that do *not* isolate their own home).

### B — `check_hat_routes` cannot read the ambient `$HOME` (#85)

`src/ralphd/engine/llm.py:100`'s `home: Path | None = None` falls back to the
ambient `$HOME` and reads `$HOME/.pi/agent/models.json`, so a start-time route
check answers according to whoever is logged in. On a host whose pi profile
routes elsewhere, the engine exits **5** before iteration 1 with
`UnroutableHatModel`.

Require the home explicitly, exactly as #83's task 002 did for `place_skills`:
the function refuses a home it was not given rather than guessing. The real call
sites (`loop.py`, `main.py`) already know the run's home. Keep the empty-provider
skip verbatim — it is what makes a fixture with no `models.json` safe.

**Acceptance:** a test that poisons `$HOME` with a `models.json` declaring an
unrelated provider and proves `check_hat_routes` does not consult it, mirroring
`tests/test_skills_placement_requires_home.py`.

### C — no ambient-`$HOME` read is left, and a new one cannot land quietly

A and B fix two consumers of one anti-pattern. Audit the rest: every
`Path.home()`, `os.environ["HOME"]`, `os.path.expanduser("~")` and equivalent
under `src/ralphd/`. Each one either takes its home from its caller, or is listed
**once** with a one-line reason why the ambient home is genuinely correct there.

Then guard it: a test that fails when a new unlisted ambient read appears. A
lexical check over `src/ralphd/` is acceptable and is the shape this repo already
uses for docs and flags — but it must name the offending file and line, and the
allowlist must carry reasons, not just paths.

### D — a third layout, one that can actually fail (#84)

Extend `scripts/host_like_pytest.sh` (a mode, or a sibling script — say which and
why) to model a developer host's **install layout and dotfiles**, not only its
environment variables:

- a user-base editable install (`PYTHONUSERBASE`) so `HOME` moves the import path;
- a `$HOME` that is **populated and hostile**: a `~/.pi/agent/models.json`
  declaring providers the fixtures do not use, and a placed skill under
  `~/.pi/agent/skills/` whose survival is checked afterwards.

Prove the layout is able to fail: with A, B and C reverted (or a documented
one-line mutation of each), it must reproduce the failures #84 lists. **A layout
that passes both before and after the fix is worthless as evidence** — record the
before/after in the sweep report.

Add the cheap static half too: no e2e/live module may construct a child engine
without either the isolated-home default (A) or the explicit opt-in.

### E — #83's disposition, stated in full

Close #83 **only if** A–D make the loss impossible, with a comment that states
what shipped, which reproducer became a regression test, and the field record
already on the issue (153 watchdog restores in one wave; three hand-observed
losses, two silent for over 2h30m). If any part of the class survives, say
exactly which and leave it open — an honest open issue beats a clean close, as
v0.11's own #83 comment established.

## Half 2 — a guard that cannot be green on one machine only (#86, #87)

### F — a report may only cite paths the repository actually contains (#86)

`tests/report_claims.py:186` accepts any cited repo path that `.exists()`.
Existence is not membership: v0.11's `task-027` report cited
`artifacts/screenshots/hub/`, a directory the browser tier *creates* and git does
not track, so the guard passed in the job's workspace and failed in every clone.

Check that a cited path is **tracked** (one `git ls-files` snapshot, not a
subprocess per claim), and keep the two failures distinguishable: *untracked*
("this path is generated, not committed — cite it absolutely if it is a run-dir
path") versus *tracked but missing* ("this path was deleted or renamed").
Absolute paths (`/run/ralphd/...`) are already ignored by `PATH_RE` and stay so.

**Acceptance:** a fixture report citing a generated-but-untracked directory
fails, with the untracked message; the same report citing the absolute run-dir
path passes; every report currently under `artifacts/reports/` still passes.

### G — a reflect that cannot parse itself is a degraded reflection, not a failed job (#87)

At v0.11's first deadline the reflect iteration returned *"no parseable 'reflect'
contract payload"* (`reflect_done ok:false`, `00:44:33Z`) and the window's
terminal record became `state: failed`, `verdict: unverified` — for a run with 25
of 30 tasks validated, `main` pushed at every boundary and five issues closed by
work that had already landed.

An unparseable reflect payload must be recorded (`reflect: {ok: false, error:
…}`, which the record already carries) and must **not** overwrite the work's own
outcome. If a reflection failure should ever be able to fail a run, it needs its
own state or fault class so the two causes are not spelled identically — decide,
implement one, and say which in the record.

This is v0.10's rule ("the clock is not a verdict") reaching one step further:
the deadline no longer produces a verdict, so the reflection the deadline
triggers must not either.

**Acceptance:** a test at the boundary — deadline fires, reflect returns garbage,
the terminal record still describes the work.

# Non-negotiables

1. **Never a full suite inside a task iteration.** Bound and background every
   sweep (`nohup timeout … &`), then poll briefly. `iteration_timeout_s` is a
   hard kill: one v0.11 iteration hit it and cost two hours and ~$9.30 for zero
   tasks.
2. **No blocking `sleep`** as a way to wait for anything.
3. **`timeout 120` on a new module's first run**, always.
4. **Stub `sup.runner`; never call `_run_iteration_once`** in a test.
5. **Never weaken a test to make it pass.** If a test must change, the commit
   message says what the old assertion claimed and why the new one is stronger.
   A: flipping the ambient-home reproducer is the one licensed inversion in this
   wave, and it is licensed *because* the behaviour it documented is being fixed.
6. **Commit and push per task.** `main` == `origin/main` at every task boundary.
7. **Sweeps sit at the true final sha**, with `git rev-parse HEAD` and
   `origin/main` shown to agree and **every skip named with its reason**. A green
   with an unexplained skip is not a green. Record all three tiers (fast,
   docker, browser) plus the new layout from D.
8. **Cleanup by exact tag and exact container name only.** Never `docker prune`,
   never a label- or wildcard-filtered `docker rm`/`rmi`.
9. **Reports cite tracked paths** (this wave's own F, applied to itself): a
   run-dir path is written absolutely, never as a repo-relative one.
10. **Do not record your own unshipped fixes as exercised.** Your engine predates
    them.
11. **Close an issue only from evidence**, and never write a closing keyword next
    to an issue number that the commit does not close.
