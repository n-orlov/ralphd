## Materiality rubric

Review computes its verdict from **blocking** findings only; **residual** findings are recorded
in the engine's run record and never reject. This section restates `docs/review-economics.md`'s
rubric for this contract and narrows nothing.

**Blocking** — any of:

- a red test at the **final code sha** (the last commit that touches anything outside
  `artifacts/reports/`, `docs/roadmap.md`, `docs/prds/README.md`);
- a requirement of this contract (A–I) not met, or a Definition-of-done predicate false;
- a false claim in a tracked artifact that changes what a reader believes **landed or its
  result**: a commit attributed for a change that shipped differently, a test result misstated,
  an issue state misreported, an invented send;
- an issue closed without evidence; a secret exposed; a weakened test or guard; a test deleted
  under C, D, E or F without the behaviour it pinned being covered by a named surviving test in
  `docs/test-suite-audit.md` § "Subsumed".

**Residual** — everything else, explicitly including: a report, roadmap block or index row that
is stale relative to commits made after it; a missing or imprecise count, sha or
cross-reference; a notification that was not sent, sent late, or not logged; a sweep or guard
record whose declared sha has a report-only gap to `HEAD`; a closing report that does not
mention a petition, adjudication, steer or ruling; formatting; prose infelicity; an inaccuracy
in a record *about another record*; the exact text of a command a task ran, its polling
cadence, a liveness check, or the shell it wrapped a launch in, when the deliverable the
command was for is present and its result verifiable; a numeric target missed **and disclosed
with its measured number** where this contract says disclosure is the fallback. A residual
finding may be listed, never used to reject, and never turned into a task by the reviewer.

## What this PRD deliberately does not ask

These clauses sank earlier runs and are banned from this contract, from this run's plan, and
from every success criterion the planner writes; plan_review refuses them:

- **No "last commit" rule; no record about its own future; no per-task notification ledger; no
  sha-scoped-count rule; no sweep-sha rule beyond the existing guard; no audit range; no
  "exactly once"; no protected-path clause; no self-referential criterion.**
- **No exact-command-line criterion.** A criterion names the *observable* a command must
  produce — a file, an exit-status file, a tally line, the sha the tree was at, a test node
  passing — never the literal text of the shell line that produced it, its wrapper, its polling
  cadence or the absence of a liveness check.
- **No criterion that demands a launch form and a captured result of the same process.**
- **No dependency on a task that can fail for a reason outside its deliverable.** Docs, report,
  record and closure tasks depend only on the code task whose result they describe, never on a
  measurement task.
- **No task whose completion requires another task's future state**, and **no task whose
  criterion is a wall-clock time.**
- **No unenumerated every/each/all quantifier**: name the members, or name the one file or
  command that bounds the set.

# The requirements

## A — the hub is cheap to leave open (#148)

Four stages, four tasks:

1. **ETag.** `GET /api/runs/<id>` serves `ETag` derived from the max mtime of `status.json`,
   `tasks.json`, `events.jsonl` and the newest iteration `meta.json`; a request carrying a
   matching `If-None-Match` receives `304` with no body. *Pinned:* a second unchanged request is
   a 304; a request after `tasks.json` changes is a 200 with a new tag.
2. **Server caches.** Iteration rows are cached per `(number, meta mtime, transcript size)`;
   shaped tasks/status blocks per file mtime. *Pinned:* a 300-iteration run dir's detail request
   derives at most two iteration rows on a warm cache (count the derivations, not the time).
3. **Client back-off.** The client sends `If-None-Match`, backs off to 15–30 s after two
   identical payloads or when the run is not `running`, and stops polling while
   `document.hidden`. *Pinned:* an in-process hub test for the header round-trip; a browser test
   for the back-off and the hidden pause.
4. **SPEC.md and `docs/architecture.md`** name the ETag, the caches and the back-off; the hub's
   existing browser suite stays green (G.1 below fixes the one node red at `7f36b7c` and this
   stage must not re-break it).
