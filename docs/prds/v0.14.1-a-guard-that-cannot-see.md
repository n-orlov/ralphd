# v0.14.1 — a guard that cannot see, and a rule that cannot finish

## Goal

v0.14 shipped nineteen requirements' worth of working code and then failed on its own record.
This is the small, honest wave that closes it out.

Its own review found the code sound: requirements C through R passed 379 focused tests, all six
suite lanes were green at their final shas, and review's independent rerun of the discovered

anyway, on four record-and-evidence findings — and two of those are real defects in the very
machinery v0.14 built to prevent them:

- **#105** — requirement A's sweep-record guard rejects pytest's parenthesized elapsed suffix,
  so it is blind to every sweep longer than 60 seconds. That is every sweep there is.

  task or an approach, most recently while the thing it guards was green.

saying `running`, a closing report that contradicts itself, and #103/#104's evidence.

**This wave is deliberately tiny. Six requirements, no new subsystems, no `loop.py` change
expected.** If you find yourself designing something, you have misread it.

## What counts as done here

The operator's disposition for this wave, and review should apply it:

- A **documentation gap, a stale sentence, an imprecise phrase in an earlier record, a missing
  cross-reference or a cosmetic defect** is **disclosed, not repaired**. One line in the closing

## Pushing, and closing issues from inside the run

The `n-orlov` credentials are mounted, not something to ask for: `--creds` places `github.env`
at `$HOME/.creds/github.env` (`GITHUB_TOKEN`, `GITHUB_USER`, mode 0600) with `gitconfig` and a
`git-credentials` entry, so `git push` and the REST API work with no setup.

- **Source the env file; never inline the token.** `set -a; . ~/.creds/github.env; set +a`. The
  token must never appear in a command you echo, a log, a commit message, a report, an issue
  comment or a Telegram message.
- **`git remote -v` prints the credential-bearing URL.** Do not run it; redact any push output
  you quote (`sed -E 's#https://[^@]*@#https://***@#g'`).
- **Verify every closure with a fresh `GET`**, never the create call's echo.

# The requirements

## A — the guard learns to read the summary line pytest actually prints (#105)

`tests/sweep_sha_guard.py`'s `PYTEST_SUMMARY_RE` ends `in +\d+(?:\.\d+)?s[ \t=]*$`. pytest
appends a parenthesized elapsed time whenever a run exceeds one minute, so both of these are
rejected today:

```
4198 passed, 1 skipped, 62 deselected in 852.84s (0:14:12)
42 passed, 2 deselected in 473.94s (0:07:53)
```

A sweep is by definition a long run, so the guard is blind to exactly the records it exists to
police. Verified at `f73e94f`: the first line returns `False`, while
`2742 passed, 46 deselected in 1122.31s` returns `True`.

- Accept an optional parenthesized suffix after the `in <n>s` group.
- **Pin both literal lines above as fixtures asserting `True`** — the shape pytest emits, not
  the shape we assumed. Add the `(0:07:53)` form too; do not pin only one.
- Keep every negative fixture green: prose that merely mentions tests passing is still not a
  sweep record.
- **Then backfill.** Every record the widened matcher newly discovers gets a declaration —
  `archived-sha` for pre-v0.14 records, per the existing vocabulary. Review named
  `a2-task-009-fast-tier-sweep.md`, `a3-task-006-browser-tier-sweep.md`,
  `task-027-docker-tier-sweep.md`, `task-029-dev-layout-exported-sweep.md` and
  `task-034-three-tier-suite-run.md`; discover the full set by running the guard, do not work
  from that list.
- `docs/sweep-records.md` says an undeclared record is out of scope and pre-v0.14 records are
  exempt. That blanket carve-out is what let this hide: shrink it to "declared with
  `archived-sha`".

**Success:** the widened matcher is pinned by the two real lines; the negatives still pass;
every report under `artifacts/reports/` that shows a pytest result line carries a declaration;
`tests/test_sweep_sha_guard.py` is green; #105 closed with the evidence.

## B — the final-sha rule gets a fixed point (#106)

"The last commit is followed by the guard subset, green, recorded" cannot terminate: recording
the result is a commit, which makes the record stale by requirement A's own correct rule. This
has cost **five consecutive waves** a task — v0.13 task 012, v0.14 approach 2 task 018, and
v0.14 approach 3 task 018, the last of these while review's own rerun at `HEAD` was green.

Give the rule a terminating step, narrowly:

- **A record commit that adds only its own guard/sweep record does not invalidate that record.**
  Implement it as parent-of-HEAD acceptance — a record whose `sweep-sha` is `HEAD~1` is current
  when `HEAD` is the commit that added that record and that commit changed nothing else — or by
  extending the existing `discharge-sha` pair to let a record anchor itself under the same
  restriction. Either is acceptable; state which and why.
- The invariant to preserve, and to say out loud in the test: **the guard subset ran green over
  every line of content that ships.** A record-only commit cannot change what the subset would
  report, which is why exempting it is sound and not a loophole.
- **Do not exempt report commits as a class.** A docs- or report-only commit really can break
  the reading guards — that is why the subset exists (#103), and v0.13's approach 2 proved it by
  reintroducing a stale test identifier in a docs-only commit. Pin that: a report commit that
  changes *another* file, or a second record commit on top, must still be caught.

**Success:** a fixture proves a record-only tip commit leaves its own record current; a fixture
proves a report commit touching anything else does not get the exemption; the rule is documented
in `docs/sweep-records.md`; #106 closed with the evidence. **This requirement is what lets
requirement F finish at all.**
