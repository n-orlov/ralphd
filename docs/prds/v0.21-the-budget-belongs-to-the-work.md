That is the thesis: **a run's budget belongs to the product, and a harness that spends it on itself
is broken.** The second half follows from the first — you cannot defend a budget you cannot see.
Today nothing answers "what did task 004 cost?", "which task is iteration 17 working on?" or "which
engine version is this run executing?", and the last of those cost v0.20 twenty-two hours on a stale
engine with its cure machinery inert and no surface saying so.

## Materiality rubric

Review computes its verdict from **blocking** findings only; **residual** findings are recorded in
the engine's run record and never reject. This section restates `docs/review-economics.md`'s rubric
for this contract and narrows nothing.

**Blocking** — any of:

- a red test at the **final code sha** (the last commit that touches anything outside `docs/`);
- a requirement of this contract (A–N) not met, or a Definition-of-done predicate false;
- a **behavioural** requirement of this contract discharged by source inspection alone, with no
  probe that would fail if the behaviour were absent;
- a false claim in a tracked artifact that changes what a reader believes landed or its result: a
  commit attributed for a change that shipped differently, a test result misstated, an issue state
  misreported, an invented send;
- an issue closed without evidence; a secret exposed; a weakened test, guard or budget ceiling; a
  retired test with no named surviving cover **in the commit message that retires it**, where the
  behaviour it pinned still exists (N.4 deletes `docs/test-suite-audit.md`; the commit message is
  where cover is named from now on).

**Residual** — everything else, explicitly including: a report, roadmap block or index row stale
relative to commits made after it; a missing or imprecise count, sha or cross-reference; a
notification not sent, sent late, or not logged; a terminal summary that does not mention a petition,
adjudication, steer or ruling; formatting; prose infelicity; an inaccuracy in a record *about
another record*; the exact text of a command a task ran, its polling cadence, or the shell it
wrapped a launch in, when the deliverable is present and its result verifiable; a numeric target
missed **and disclosed with its measured number** where this contract says disclosure is the
fallback; **a UI refinement in I that lands with a different affordance than the sketch describes,
where the stated behaviour holds.** A residual finding may be listed, never used to reject, and
never turned into a task by the reviewer.

**Explicitly NOT a finding of any severity** — this contract asks for these removals by name, and a
finding that the removed thing is missing is a finding against the contract itself:

- **every deletion requirement N makes**: `artifacts/reports/` and each of its 317 files,
  `docs/test-suite-audit.md`, `docs/sweep-records.md`, `docs/testing.md`'s count and
  collection-budget rows, the tracked `*-petitions.md` files, and the 38 test modules' coupling to
  the report corpus;
- **the absence of a closing-report file**, of a lane record, of a count disclosure, of an
  attestation artifact, and of narrative in an index row;
- **a lane result present only as a run id and URL** in a commit message and nowhere in the tree
  (M.2), and **a lane run that names the final code sha while the tip is a later docs-only commit**
  (M.1 — this is #199, and chasing it cost the last three waves a rejection each);
- **a prior wave's roadmap block or index row left exactly as it is.** N.5 makes what remains of the
  record set unmaintained history: a stale claim in it is history, and a wave that "fixes" one is
  doing the thing N exists to stop. 56 such commits landed in the seven days before this wave.

## Petitions and late cure

The petition protocol and late-cure rule of `docs/review-economics.md` apply. Petitions go in
`artifacts/reports/v0.21-petitions.md`, committed ahead of launch; the run never adjudicates its own
petition and never records an adjudication it has not received. A missed duty is cured late and
labelled late; a late cure is a residual, not a finding.

**That file is the one survivor of requirement N, and you do not delete it.** N.6 stops the engine
writing petitions into the tree at all — but the engine *running you* still appends to the last
`*-petitions.md` it finds under `artifacts/reports/` (#150), so deleting it mid-run would leave your
own engine dirtying a tree you must keep clean at every task boundary. So: N deletes the corpus and
leaves `artifacts/reports/v0.21-petitions.md` behind, alone in the directory, for the operator to
remove after the run ends. Say that in one line where you record N.1, and do not petition about it.

**You are fixing the petition deadlock (C) on an engine that still has it.** Until C ships, a
petitioned task can hold every task that reaches it through `dependsOn` and the engine will keep
handing you no-task worker iterations against a graph it can prove is unselectable. Therefore, when
you petition: **`notify` in the same iteration**, naming the held task, the tasks that depend on it,
and the concrete decision you need. Then stop re-deriving the block. In v0.20, one notification got
the operator's release in 16 minutes; seventy identical correct diagnoses got nothing.

**Foreign petitions.** Adjudication episodes will list v0.15–v0.20.2 petitions from older
`*-petitions.md` files as open. They are not yours. Treat any petition whose obligation names no
task in the current `tasks.json` and no requirement of this contract as history.

## What this PRD deliberately does not ask

These clauses sank earlier runs and are banned from this contract, from this run's plan, and from
every success criterion the planner writes; plan_review refuses them:

- **No "last commit" rule; no record about its own future; no per-task notification ledger; no
  sha-scoped-count rule; no audit range; no "exactly once"; no protected-path clause; no
  self-referential criterion.**
- **No exact-command-line criterion.** A criterion names the *observable* a command must produce —
  a file, an exit-status file, a tally line, a test node passing — never the literal text of the
  shell line that produced it, its wrapper, or its polling cadence.
- **No criterion that demands a launch form and a captured result of the same process.**
- **No dependency on a task that can fail for a reason outside its deliverable.** Docs, report,
  record and closure tasks depend only on the code task whose result they describe, never on a
  measurement task.
- **No task whose completion requires another task's future state**, and **no task whose criterion
  is a wall-clock time.**
- **No unenumerated every/each/all quantifier**: name the members, or name the one file or command
  that bounds the set. **This is a lexical lint, not a semantic one** — see § "Standing rules"; it
  killed two of v0.20's eight approaches outright. B fixes the re-prompt, not the lint's existence,
  and B's fix does not reach your own plan.
- **No new required field on any hat contract or findings schema.**
- **No committed record whose subject is this wave's own work** — not a test result, not a lane
  result, not a closing report, not a count disclosure, not an attestation that a requirement was met.
  Cite run ids and URLs in commit messages; the evidence a judge needs is the test, the lane and the
  run dir. Requirement N removes the machinery; this bullet stops it growing back inside this plan.
- **No task whose deliverable is a tracked prose file**, and no more than **three** record-only tasks
  in the whole plan (N.8 names them: the roadmap block, the closures, the terminal summary).
- **No change to the runner-slot layout on the CI host**, and no new self-hosted runner: that is
  operator configuration. See K.
- **No fix to #25** (parked by the operator 2026-09-07), **#134's bypassability half**, or the
  deferred items in `docs/roadmap.md` § "Later / explicitly deferred".

## Sequencing and planning rules

Flat plan, **at most 5 checkable clauses per task**, wave-wide rules in the Standing Rules block
once. **Every task is one worker iteration.** Dependencies are data dependencies only: A–E's code
tasks depend on nothing; a probe task depends only on the code task it probes; G's tasks depend on

and **I** (both read F's fields), then **H**, then **J**, then **K**, then **L**. **H may be pulled
forward at any point** — it touches one endpoint and its own caches, it collides with nothing else in
this wave, and the operator is watching this run through the surface it fixes. Then **N**, then **L**, then
**M** last.

**N is not last, and that is deliberate.** It removes the checks and records that made the last three

# The requirements

## A — a curable rejection on the last approach gets a cure pass (#192)

The peer `verdict_gate` fires only after review returns `verified`, so in the worst case its first
pass is also the run's last. v0.20 ended holding four findings it had already established were
curable, each with a written `Cured when:` clause, and no budget to act on them. An operator reading
`ralphctl status` could not tell that from a rejection on the merits.

**A.1** When the gate rejects and **every** blocking finding it returned is marked curable, the run
schedules the cures instead of ending — through a cure pass that does **not** consume a fresh
approach's replan, and does not archive the approach. Name the mechanism in the commit: a reserved
cure pass, a cure-only approach, or an extension of the existing `insert_cure_tasks` path.

**A.2** The cure pass is **bounded and declared**: a configured ceiling on how many cure passes a
run may take, its default stated in `docs/api.md` or `docs/cli.md`, and a named test proving a run
cannot loop cure→reject→cure indefinitely.

**A.3** A gate rejection carrying **any** non-curable blocking finding still ends the run. A named
test covers the mixed case, so A.1 cannot be read as "the gate can no longer fail a run".

**A.4** The terminal record distinguishes the three endings in a field an operator surface reads —
rejected on the merits, rejected with a cure path taken, rejected with a cure path **not** taken
(budget exhausted) — and `ralphctl status` words each differently. A named test asserts the wording
for each of the three.

**A.5** Probe A.1 and A.3 by driving the supervisor fixture (as v0.20's gate did with
`_progressing_approach_supervisor`), not by observing this run. State in the commit which fixture
drove it.

## B — planning never costs an approach for zero work (#135)

Two of v0.20's eight approaches died in planning to a **lexical** style lint, after 3 ingestion
refusals each, having produced nothing. One of them refused the same task three times while the
offending clause shrank to `(5) This task makes no commit`.

**B.1** An ingestion refusal re-prompts the planner with the lint's **own suggested rephrasing**,
not only the rule it broke. The lint already names the offending clause; the re-prompt carries a
concrete legal rewrite of it. A named test asserts the suggestion text reaches the planner's next
prompt.

**B.2** A clause whose universal set is bounded elsewhere in the same task's criteria stops being a
hard refusal. Name the rule you implemented and its limit; a named test covers one clause that is
now accepted and one that is still refused, so B.2 cannot be read as disabling the lint.

**B.3** A planning death costs iterations, not an approach — or, if the two-strike ingestion
termination is kept as-is (it is correct, and #135 says so), the **terminal reason** names the
lexical lint and the exact clause, and the approach that died in planning is not counted against
`max_approaches`. Pick one, say which, and cover it with a named test.

**B.4** A refused worker split no longer vanishes: the worker gets the lint text back through its
existing re-ask ladder, or at minimum the refusal reaches its next prompt. A named test asserts a
refused split is visible to the worker rather than only logged.

**B.5** The lints themselves are **not weakened**. `docs/review-economics.md` or the plan-ingestion
docs state that the quantifier and clause-count checks are lexical by design, and why.

## C — a petition can never deadlock a run (#187)

The mid-run adjudication episode is the only thing that can resolve a petition, and it is dispatched
by two unrelated state conditions with a hole between them. v0.20 lost ~85 iterations and 3.6 hours
to that hole, twice, spinning no-task worker iterations the stagnation guard could not rescue.

**C.1** A task entering `petitioned` **itself** triggers the adjudication episode. Name the trigger
point.

**C.2** A named test builds the exact deadlock shape from #187 — one `petitioned` task, every other
open task reaching it through `dependsOn`, directly or transitively — and asserts the episode
dispatches rather than the engine issuing no-task worker iterations.

**C.3** When no task is selectable **and** the reason is a `petitioned` task, the engine says so on
a surface the operator reads, once, naming the held task and its dependents. Not once per iteration.

**C.4** A named test asserts a run whose only block is a petition does not burn its iteration
budget: the no-task iteration count stays under a stated bound.

**C.5** `skipped` is not a resolution and the engine does not offer it as one. Nothing in this
requirement adds an edge back to `pending` — that edge does not exist by design and this wave does
not create it.

## D — an operator instruction the engine will not honour (#184, #133, #196)

Two halves of one disease: the operator writes something through a channel the engine offers, the
engine accepts the write, and then does not honour it. **D.1–D.6** are the steer channel writing
state the picker will not enforce. **D.7–D.13** are the ruling channel losing its authority at a
replan boundary — the most expensive instance of this wave's thesis on record, because the harness did
not merely waste the budget, it spent a night **undoing the operator's own authorised work**.

What happened, since D.7–D.13 are written against it: v0.20.1's operator recorded two rulings with
`ralphctl amend`, authorising a retirement. `amend` requires a **task id**. Approach 1 executed the
rulings, was rejected four times for unrelated reasons, and replanned — and a replan restarts task
ids at `001`. Both rulings now named task ids that did not exist, so `loop.py`'s ruling-context
builder re-rendered them to the judging hats under *"Historical rulings (not binding this review) …
**NOT authoritative for this review**"*. Review reasoned correctly from the context it was handed,
found guard removals with no visible authority, and returned two blocking findings **ordering them
reverted**. A cure pass and twelve tasks obliged. Filed as **#196**.

The approach-scoping itself is not the bug — it is #168's deliberate design and D.13 keeps it. The bug
is that `amend` has no way to express a ruling whose subject is the **wave or the PRD** rather than one

occasion and inherits that task's mortality.

## H — watching a run stops costing a core and a gigabyte (#195)

`GET /api/runs/<id>/logs` — the endpoint the run-detail page's transcript box polls — fetches the
run's **entire** raw backlog from the container, renders every line, then trims to the last 200.
`rendered_log_lines` (`src/ralphd/cli/ui_server.py:429`, as filed — re-locate before editing) says so
in its own docstring, and states the reason: `N` means N *rendered* lines, so trimming raw events
first would yield a wildly variable visible count once the renderer collapses event types. **The
contract is right; the cost is the defect.** Measured on the operator host on 2026-09-12 against a
run with 176 MB under `iterations/`:

```
GET /api/runs/<id>                      0.014 s     249 394 B
GET /api/runs/<id>  + If-None-Match     0.001 s     304, empty      <- #148's fix, working
GET /api/runs/<id>/logs                 2.259 s      17 139 B       1.72 s CPU
   the identical request, immediately    4.506 s      13 844 B       2.49 s CPU   <- costs MORE
```

RSS during that minute ranged 352 868 kB → 1 153 316 kB; cumulative CPU was 83 % user-space, which
rules out the accept loop. #148 fixed the run-detail payload and is legitimately closed; **its memory
half was never examined** — its own body called for a `tracemalloc` pass and the closure did not
include one.

**H.1** A log-tail request costs work proportional to the **tail**, not to the run's history. Render
backwards from the end in bounded chunks until `N` rendered lines exist, growing the window when a
chunk yields fewer. `log_render`'s collapse guards are order-dependent, so name the restart point you
chose; a naive reversed scan changes what the operator sees.

**H.2** The rendered output is **identical** to today's for the same run and tail — same lines, same
collapse behaviour, byte for byte. A named test asserts equality between the old full-render path and
the new bounded one on a fixture with a many-delta thinking block, and on a dead run served from the
on-disk merge. **This is the requirement that makes H safe: a cheaper tail that shows something else
is a regression, not an optimisation.**

**H.3** `GET /api/runs/<id>/logs` is conditional and cached: an `ETag` over the same inputs #148
used, honouring `If-None-Match` with a `304`, plus a rendered-tail cache keyed by the newest
iteration and its transcript size. A named test asserts a second identical request does no
re-rendering, and a named test asserts a `304` when nothing has moved.

**H.4** A live run's log fetch no longer asks the container for an unbounded backlog: pass a bound
derived from H.1 and re-ask when the render comes up short of `N`. A named test covers the re-ask.

**H.5** The derivation caches are **bounded** — `_ITERATION_ROW_CACHE`, `_TASKS_BLOCK_CACHE` and
`_STATUS_BLOCK_CACHE` are today evicted only when a run is deleted. Add a cap or an LRU, with a named
test proving the bound holds after entries for more runs than the cap.

**H.6** A stated, measured budget, recorded in the commit and in `docs/architecture.md`: with one tab
open on a running job with at least 100 iterations, the hub's CPU over a 60-second sample and its
peak RSS, both named with numbers. A named test — not a wall-clock assertion, which this PRD bans —
pins the **work**: the number of iteration transcripts read to serve one 200-line tail is bounded by
a constant, not by the iteration count.

**H.7** The client's transcript poll shares the run-detail poll's back-off and hidden-tab pause. If
it already does, say so with the node id that proves it; if it polls on its own timer, wire it in. A
browser-tier test covers a hidden tab issuing no log-tail request.

# Standing rules the planner carries over verbatim

- **The clause and quantifier lints are LEXICAL, and they killed two of v0.20's eight approaches.**
  Before you report a plan path: count your own clauses the way the engine does (split on
  `[.!?;]+(?=\s|$)`, count non-empty fragments, cap 5), and grep your own proposal for `every`,
  `each`, `all`, `any`, `none of`, `no … anywhere` and `both` with unnamed members. The check is
  **textual** — avoid the words, not merely the unbounded meaning. Two legal rewrites: name the
  members inline, or name the one file or command that bounds the set. **Requirement B improves the
  re-prompt for a future wave; it does not help you.**
- **Prove engine behaviour against a fixture or an installed clone, never against your own run.**
  The process running you has the old behaviour for its whole life. Name the fixture or the clone
  path in the commit message.
- **Assert what your venv resolves.** `ralphd.__file__` inside the tree you mean to measure, in the
  same iteration as the measurement.
- **Test commands.** Fast tier: `pytest -q -m fast -n 8 --dist loadfile`. Guard subset:
  `scripts/final_sha_guards.sh`. Targeted: `pytest -q <node>` in seconds — prefer it, always under a
  `timeout`. At most one full fast-tier run per iteration. After an `-n 8` run, re-verify a
  suspicious red **solo** before believing it. Every process wait has a deadline of at most 20 min;
  then `kill -INT` your own recorded pid and read its log — a summary printed after your own SIGINT
  lists only what COMPLETED; node ids missing from it are stuck, never passed.
- **Read your own newest CONCLUDED `gate` run at the start of each task.** `cancelled` and
  `in_progress` are not verdicts. If the newest concluded one is `failure`, the red is one commit
  old, not twenty: cure it inside the task you are starting, or insert a task for it before
  continuing.
- **Records hygiene, after N: there is almost none left.** v0.20.1 and v0.20.2 retired the sweep-sha
  practice, the conformance-ledger checker and the result-line/historical-node-id claim checks; **N
  retires the rest.** The only record duties that survive this wave are: a new run-dir file, API route
  or `RUN_DOCUMENTS` key updates SPEC.md in the same commit; a retired test names its surviving cover
  in the commit message that retires it; any sha you cite is reachable from `HEAD`. **A duty naming a
  file N deleted does not exist — do not recreate the file to satisfy it.** Read from the tree at
  launch: `tests/records/` is five modules — `test_report_claims.py`, `test_roadmap.py`,
  `test_records_family_budget.py`, `test_records_family_fresh_clone.py`,
  `test_ralphctl_process_boundary.py` — and `docs/sweep-records.md` is already gone (v0.20.2 deleted
  it). The report-claim checks in the first of those are what N.2 retires.
- **Never weaken a test to reach green.** No deleted or loosened assertion, no raised budget
  ceiling, no weakened guard or prompt strictness — re-shape how a test drives the loop instead. A
  *scenario parameter* (a value that constructs the situation under test) may be sized so a
  deliberately-healthy path is not misclassified; a *patience timeout* (how long a harness waits)
  may not be widened. Keep `tests/conftest.py`'s `RALPHD_NOTIFIER_URL` scrub alive.
- **Docker siblings.** Label with `ralphd.run=$RALPHD_RUN_ID` and `ralphd.role=sibling`,
  `--user 1000:1000` unless the test's subject is the uid boundary itself (E.2), host paths
  `$RALPHD_HOST_WORKSPACE`/`$RALPHD_HOST_RUN_DIR`. Never touch a container, image or process you did
  not create.
- **Commit titles.** `<area>: <what changed> (task <id>, requirement <letter>)`.

# Non-negotiables

   yourself.
2. Never weaken a test, guard, budget ceiling or a prompt's product strictness to force green.
   Retiring a test is legal only with a named surviving cover, or an operator ruling authorising the
   retirement.

9. No committed record whose subject is this wave's own work: no test result, no lane result, no
