# v0.19 — a note is not a rejection

## Goal

v0.18 shipped the review-side exits: a rubric that reaches review, a cure pass, a pause instead
of `failed` on the last approach. Its own run then ended `failed` anyway, on a guard nobody had
looked at: the worker-side stagnation detector, after a 96-minute iteration that pushed ten
commits (#153). The first run on 0.18.0 (`deck-phase3k`) exercised every new edge correctly —
cure pass, doomed-set routing, adjudication with a remedy — and still spent 3.5 hours and four
attempts re-measuring a ten-run stability gate that passed 10/10 the first time, because the
verifier rejects delivered work on the *form* of its launch line and has no way to pass with a
note (#154). Meanwhile the fast tier alone takes 16 minutes for ~6200 tests, most of them
single-fact pins, and every lane the run must re-run at its final code sha costs the wave an
hour or more.

This wave (#148–#154) closes the remaining non-work ways a run ends, gives the verifier the
same materiality standard the reviewer has, and makes the suite the run has to keep green
small enough to be kept green:

- **A (#154)** — **the verifier accepts delivered work**: the rubric reaches verify, a pass can
  carry notes, notes become a cooperative debt ledger that later workers and review consume.
- **B (#153)** — **progress is what the run did, not what `tasks.json` says**: the stagnation
  guard sees commits and tool activity, routes a long-absorbing task to verify, and pauses
  instead of failing on the last approach.
- **C (#149)** — **a `petitioned` dependency holds, it does not starve**: dependents are visible,
  the adjudication episode is triggered, a CONFIRMED petition closes the loop, and a cure task
  that supersedes a dead task inherits its dependents.
- **D (#151)** — **an infra fault never trips the instant-failure breaker**.
- **E (#150, #152)** — **petitions belong to their wave and adjudications survive a resume**.
- **F (#148)** — **the hub is cheap to leave open**.
- **G** — **the suite is small and fast**: consolidated black-box flow cases, a smoke tier for
  verify, parallel execution, a fast tier under a hard minute budget.
- **H** — version 0.19.0, the roadmap block, this wave's row, `LAUNCH_SHA`.
- **I** — the suite green at the final code sha, the closures, the closing report, the terminal
  summary — each defined so it can be true.

## Materiality rubric

Review computes its verdict from **blocking** findings only; **residual** findings are recorded
in the engine's run record and never reject. This section restates `docs/review-economics.md`'s
rubric for this contract and narrows nothing.

**Blocking** — any of:

- a red test at the **final code sha** (the last commit that touches anything outside
  `artifacts/reports/`, `docs/roadmap.md`, `docs/prds/README.md`);
- a requirement of this contract (A–I) not met, or a Definition-of-done predicate false;
- a false claim in a tracked artifact that changes what a reader believes **landed or its
  result**: a commit attributed for a change that shipped differently, a test result misstated,
  an issue state misreported, an invented send;
- an issue closed without evidence; a secret exposed; a weakened test or guard; a test deleted
  under G without the behaviour it pinned being covered by a named surviving test.

**Residual** — everything else, explicitly including: a report, roadmap block or index row that
is stale relative to commits made after it; a missing or imprecise count, sha or
cross-reference; a notification that was not sent, sent late, or not logged; a sweep or guard
record whose declared sha has a report-only gap to `HEAD`; a closing report that does not
mention a petition, adjudication, steer or ruling; formatting; prose infelicity; an inaccuracy
in a record *about another record*; the exact text of a command a task ran, its polling
cadence, a liveness check, or the shell it wrapped a launch in, when the deliverable the
command was for is present and its result verifiable. A residual finding may be listed, never
used to reject, and never turned into a task by the reviewer.

## Petitions and late cure

The petition protocol and late-cure rule of `docs/review-economics.md` apply. Petitions go in
`artifacts/reports/v0.19-petitions.md` (committed ahead of launch so the 0.18.0 engine's
`files[-1]` targeting lands them there, #150); the run never adjudicates its own petition and
never records an adjudication it has not received. A missed time-anchored duty is cured late
and labelled late; a late cure is a residual, not a finding.

**Foreign petitions.** Until E ships, adjudication episodes in this run will list v0.15–v0.18
petitions from older `*-petitions.md` files as open. They are not this run's. Do not act on
their remedies, do not re-send their notifications, do not edit their files. Review: treat any
petition whose obligation names no task in the current `tasks.json` and no requirement of this
contract as history.

## What this PRD deliberately does not ask

These clauses sank earlier runs and are banned from this contract, from this run's plan, and
from every success criterion the planner writes; plan_review refuses them, and E's lint from
v0.18 refuses most of them already:

- **No "last commit" rule; no record about its own future; no per-task notification ledger; no
  sha-scoped-count rule; no sweep-sha rule beyond the existing guard; no audit range; no
  "exactly once"; no protected-path clause; no self-referential criterion** (all as v0.18).
- **No exact-command-line criterion.** A criterion names the *observable* a command must
  produce — a file, an exit-status file, a tally line, the sha the tree was at, a test node
  passing — never the literal text of the shell line that produced it, its wrapper, its
  polling cadence or the absence of a liveness check. The deck-3k task 205 shape ("launched as
  `nohup timeout … &` and polled with `sleep 120` and nothing else" *and* "the captured exit
  status") is the must-catch fixture for A.5.
- **No criterion that demands a launch form and a captured result of the same process.** If a
  result must be captured, the criterion says what file holds it and lets the worker choose the
  wrapper.
- **No dependency on a task that can fail for a reason outside its deliverable.** Docs, report,
  record and closure tasks depend only on the code task whose result they describe, never on a
  measurement task; a failed measurement is reported, not waited for.
- **No task whose completion requires another task's future state.**

## Sequencing and planning rules

Flat plan, ~5 checkable clauses per task, wave-wide rules in the Standing Rules block once.
Land engine code before anything that must be green because of it. **Land G's suite
restructuring before I's lanes**, so the lanes are the new, shorter suite. Lane sweeps at the
final code sha: **one task launches every lane in the background; one task records every lane
in one commit** — never one task per lane, never a record commit that makes the previous
record stale and then a task to re-record it (the v0.18 approach-2 fixed point). A report-only
tail after the records is permitted by the guard; nothing is re-run for it. Dependencies are
data dependencies only. One honest attempt per task; deviations stated, never silent.

## Where work happens

`/workspace` is a checkout of this repository at `origin/main` as of launch. Commit and push per
task; `main` == `origin/main` at every task boundary. The host running you also runs another
ralphd job and its sibling containers: never touch a container, image or process you did not
create, never `docker prune`, never signal by pattern.

## Pushing, and closing issues from inside the run

`--creds` places `github.env` at `$HOME/.creds/github.env` (`GITHUB_TOKEN`, `GITHUB_USER`) with
`gitconfig` and `git-credentials`; push and the REST API work with no setup.

- **Source the env file; never inline the token** (`set -a; . ~/.creds/github.env; set +a`). The
  token never appears in output, commits, reports, comments or messages.
- **Do not run `git remote -v`**; redact any quoted push output
  (`sed -E 's#https://[^@]*@#https://***@#g'`).
- **Verify every closure with a fresh `GET`.** Never write a closing keyword + issue number in a
  commit message unless that commit closes that issue.

## Telling the operator what is happening

The engine's `notify` hat tool is configured (`RALPHD_NOTIFIER_URL`) and records every send as
a `notification.sent` event; **use it, not a direct POST** — the placed `telegram-notify` skill
says the same. The operator is AFK and reading Telegram, not the log.

Send, best-effort: plan accepted; each approach rejection or cure pass; each lane record with
its result line; each closure with its URL; anything that needs an operator decision (say what
you need, then petition — do not wait); the terminal summary. Sends are advisory: **a failed or
missed send is never a task failure, never a criterion, never a finding above residual.**

# The requirements

## A — the verifier accepts delivered work (#154)

1. **The rubric reaches verify.** The verify prompt receives the same resolved materiality
   rubric review receives (`findings.resolve_materiality_rubric`, inline / by-reference / engine
   default) and a verify-specific rule: reject only when a criterion's *deliverable* is absent or
   wrong, a named test fails, a factual claim in a record is false, a command the criterion
   names was never run, or a secret is exposed; form, wording, provenance and process clauses
   (exact command text, wrapper, polling cadence, liveness checks, the sha a docs-only-identical
   tree launched from) **verify with a note**. `task-verify.md`'s "Be strict" paragraph is
   rewritten to say this; "disclose on tails" becomes a special case of it. Pinned lexically and
   by an in-process test that a verify prompt carries the rubric text.
2. **A pass can carry notes.** `HAT_SCHEMAS["verify"]` accepts `verdict: "verified"` with an
   optional `notes` array of `{clause, observed, suggested}` objects (and still accepts a plain
   `reason` string). `_verify_task` persists them on the task record as `verifyNotes` in the
   same write that sets `validated`. Schema stays `additionalProperties: false`.
3. **A debt ledger.** Every `verifyNotes` entry is appended by the engine, through one write
   path in `engine/state.py`, to the run dir's `debt.json` (and a rendered `debt.md`): `{id
   "<task>/<n>", taskId, clause, observed, suggested, ts, status: open|resolved, resolvedBy}`.
   The worker prompt carries an `## Open debt` block (like the steering ledger) stating it is
   optional and bounded: a worker MAY resolve an item while on its own task when it costs
   minutes and stays inside its task's files, and reports `"debt_resolved": ["<id>", …]` beside
   its completion payload; the engine marks the item `resolved` with the iteration's commit sha.
   Review receives the ledger as pre-classified residuals it may confirm or, with evidence,
   promote to blocking — never rediscover. The run record renders open and resolved debt.
   `ralphctl docs <run>` shows `debt.md`; the hub links it.
4. **Adjudication remedies that are only about form** (the remedy changes no deliverable, only
   how it is produced) are recorded as debt items, not as `validationNotes` driving a retry:
   the mid-run adjudication's REFUTED path classifies the remedy (`form` vs `substance`) and
   routes accordingly; `substance` behaves exactly as today.
5. **The lint learns the shape.** `plan_ingestion.lint_proposal()` (v0.18's seventh lint or an
   eighth) refuses a criterion that pins the literal text of a shell command, a wrapper, a
   polling cadence or a "nothing else" clause, and a criterion that both pins a launch form and
   demands the same process's captured status; the deck-3k task 205 criterion is the verbatim
   must-catch fixture; a criterion naming the observable ("`summary.log.exitstatus` holds the
   script's exit status") is the must-pass sibling.
6. Pinned at the in-process tier: verified-with-notes persists `verifyNotes` and a debt item;
   a worker's `debt_resolved` flips it; review's context contains the open ledger; the run
   record renders it; a `rejected` verdict is unchanged.

## B — progress is what the run did (#153)

1. **Progress has more than one witness.** The stagnation counter treats an iteration as
   progress when any of: `tasks.json` changed; the workspace branch gained commits since the
   iteration started; the worker's contract payload was `complete`, `unsatisfiable` or a
   petition; the transcript shows non-trivial tool activity (a threshold in
   `LoopSupervisor`, documented). Only iterations with none of these count towards stagnation.
2. **A task that absorbs iterations is judged, not starved.** When one task has taken N (=3,
   configurable) consecutive worker iterations with commits but no completion signal, the
   engine moves it to `awaiting-validation` on the worker's behalf with a `notes` entry saying
   so and routes to verify; verify judges the tree as-is under A.
3. **On the last approach, stagnation never ends `failed` silently.** A genuinely stagnant last
   approach takes the `rejected_last_approach` pause (v0.18 D.1) with `reason:
   stagnation`, an `operator_escalation` event and a notification; `resume` re-enters the same
   approach. The declared transition table and its mermaid gain the edge.
4. Pinned at the in-process tier for: commits-only progress, the N-iteration hand-off to
   verify, the last-approach pause, and the unchanged behaviour for a genuinely silent approach
   with approaches left.

## C — a `petitioned` dependency holds (#149)

1. **Visible.** A dependent of a `petitioned` task appears in the blocked map with the
   petitioned task as cause, on `ralphctl tasks`, the hub, `GET /tasks` and the worker prompt.
2. **Held, not starved.** Iterations in which the only unscheduled work waits on a
   `petitioned` task do not count towards stagnation; when nothing else is schedulable the
   engine triggers the mid-run adjudication episode immediately instead of idling.
3. **Closed by CONFIRMED.** A CONFIRMED adjudication moves the petitioned task to `skipped`
   with the adjudication in `notes` (the obligation is void) **and re-points every dependent's
   `dependsOn` from it to nothing** (or to the replacement task the adjudication names), in the
   same pass that records the confirmation. A REFUTED adjudication behaves as today.
4. **A cure inherits dependents.** When the cure pass appends a cure task for a finding whose
   evidence names a `failed` task, every dependent of that failed task gets the cure task added
   to its `dependsOn` and the failed task removed, so the plan has no doomed remainder once the
   cure lands. `steer.md` documents the same move for the steer hat (`task-update` with
   `dependsOn`).
5. Pinned at the in-process tier for all four.

## D — an infra fault never trips the breaker (#151)

1. `_check_instant_failure` ignores an attempt whose fault class is `infra`; the infra outage
   budget and backoff ladder govern it alone. The streak still counts instant failures with no
   infra signature.
2. `reflect` after any abort retries under the same infra ladder (bounded) instead of one
   attempt.
3. Pinned: an infra-classified instant-exit streak of 5 does not abort while the budget has
   time; a credential-shaped streak of 3 still does.

## E — petitions belong to their wave, adjudications survive (#150, #152)

1. **Scoped discovery.** `open_petitions_in_workspace` reads only the current wave's file
   (`<wave>` as `ensure_petitions_file` derives it) and treats a petition whose obligation names
   no task in the current `tasks.json` and no requirement of the contract as history.
2. **The engine writes back.** When `petition_adjudications_recorded` fires, the engine appends
   `**Adjudication**: CONFIRMED|REFUTED — <remedy>` to the petition's own section in the
   tracked file (it already owns `file_exhaustion_petition`) and commits it with the run's git
   identity if the workspace is clean; a dirty workspace defers to the next task boundary.
3. **`file_exhaustion_petition` targets the current wave's file**, creating it if absent, never
   `files[-1]`.
4. **The MAC key survives resume.** `ralphctl start`/`resume` bind a mode-0700 host directory
   (`~/.ralphd/configs/<run>/run-secrets/`) at `/var/lib/ralphd/run-secrets`; when no key is
   available the `events.jsonl` witness (`petition_adjudications_recorded` carries the MAC) is
   the fallback check, and `ralphctl status`/`doctor` name the condition.
5. Pinned at the in-process tier and by one `ralphctl` CLI test for the mount.

## F — the hub is cheap to leave open (#148)

1. `GET /api/runs/<id>` serves `ETag` from the max mtime of `status.json`, `tasks.json`,
   `events.jsonl` and the newest iteration `meta.json`; the client sends `If-None-Match` and
   receives `304` when nothing moved.
2. Iteration rows are cached per `(number, meta mtime, transcript size)`; shaped tasks/status
   blocks per file mtime.
3. The client backs off to 15–30 s after two identical payloads or when the run is not
   `running`, and stops polling while `document.hidden`.
4. Pinned: a second unchanged request is a 304; a 300-iteration run dir's detail request
   derives at most two iteration rows on a warm cache; a browser test for the back-off.

## G — the suite is small and fast

The audit in `docs/test-suite-audit.md` (committed with this PRD) is the baseline and the map.
Its measured facts: fast tier **981 s** (16:21) for **6,230** tests in **383** modules; the
slowest 80 tests sum to **599 s** and are all real engines, real sleeps and subprocess spawns
(one mutation test alone is 80 s, in an unstubbed backoff); ~4,000 in-process prose/pin tests
cost ~100 s; **44** modules spawn a real engine with the stub `pi`, **87** define their own
`_supervisor()` harness, **65** modules are named per task (451 tests), **64** shell out to
`ralphctl` (159 spawns), `test_report_claims` alone is 1,095 tests; petition/adjudication and
the last-approach pause have **no** real-engine coverage; nothing blocks `pytest-xdist`. G lands
**before** I's lanes, in this order (the audit's § 4(f)), each step with its own task:

1. **Shared harness.** conftest fixtures `supervisor(tmp_path, **cfg)` and
   `scripted_attempts(sup, [...])` with every backoff and sleep stubbed by default; the 87
   `_supervisor` copies and `test_e2e.EngineProc` deleted. *Criterion:* `grep -c 'def
   _supervisor(' tests/` is 0; no fast-tier test exceeds 10 s.
2. **No real sleeps.** `_wait_out_backoff` stubbed in every in-process test; `STUB_SLEEP=0`
   and zero backoff config in every stub-`pi` test; durations asserted by deadline-polling,
   never by sleeping. *Criterion:* the `--durations=80` sum is under **120 s** (from 599).
3. **Parallel.** `pytest-xdist` as a dev dependency; the two direct `os.environ` writes and the
   `free_port()` race fixed; the `AMBIENT_HOME` modules and the nested-pytest test in an
   `xdist_group`; the recorded fast-tier recipe becomes `-n 8 --dist loadfile`. *Criterion:*
   green at `-n 8` three consecutive runs, wall clock under **4 min**.
4. **One records-lint family** in `tests/records/`, selected by directory in
   `scripts/final_sha_guards.sh`: `test_report_claims` collapsed to iterate all reports in
   ≤ 10 tests, `test_conformance_ledger` with one in-process collection instead of 68
   subprocesses, the eight `test_roadmap_v0N.py` folded into one, one mutation twin per
   *checker*, never per fact. *Criterion:* ≤ **300** tests, < **15 s**, zero subprocesses but
   one `git ls-files`.
5. **Twelve stub-`pi` flow modules**, one per loop path (the audit's list: happy path and exit
   modes; validation rejection → retry → three strikes → review and tamper refusal; review
   rejection → replan → exhaustion → last-approach pause → resume; cure pass variants;

   `STUB_SLEEP=0`, each asserting the `events.jsonl` **sequence** and the whole observable
   record, each naming the failing step. *Criterion:* real-engine modules ≤ **14**; each flow
   < 20 s serial; petition/adjudication and last-approach pause covered end-to-end.
6. **Per-task pins folded** into one feature module each (last-approach, cure pass, contract
   ladder, steer, petitions, transitions). *Criterion:* `ls tests/test_*_task*.py` is empty;

7. **CLI in-process.** `ralphctl` tests call `cli.main.main()` with argv and `capsys` except
   the five process-boundary modules the audit names. *Criterion:* `RALPHCTL` spawns in ≤ 8
   modules; the cli family under 30 s.
8. **Tiers and a budget guard.** `smoke` (in-process flows, in-process CLI, records lint, hub

# Non-negotiables

1. A non-zero pytest exit at the final code sha is RED; petition once per obligation, never
   waive yourself.
2. Never weaken a test, guard or a prompt's product strictness to force green. Deleting a test
   under G is legal only with a named surviving cover in the § "Subsumed" table.
3. The run never grants itself a severity, a curability, a petition outcome or a criteria
   amendment; the PRD and `/config` are amendable by no one inside the container.
4. Closures carry evidence, fresh-`GET` verified; no closing keyword + issue number in a commit
   message unless that commit closes that issue.
5. `main` == `origin/main`, clean tree, at every task boundary.
6. Secrets never appear anywhere.
7. Flat plan, sequencing rule, bounded criteria, none of the banned clause shapes; one task per
   iteration, every iteration ends with a status change.

# Definition of done — predicates, each owned by a named task

1. A verify prompt carries the resolved rubric and the deliverable-vs-form rule; a
   `verified` payload with `notes` persists `verifyNotes` and a `debt.json` item; the worker
   prompt shows open debt; `debt_resolved` flips an item; review's context carries the ledger;
   the run record renders it; the lint refuses the task-205 fixture and passes the observable
   sibling (#154).
2. An iteration with commits and no `tasks.json` change is progress; a task absorbing N
   iterations with commits is handed to verify; stagnation on the last approach pauses with
   `reason: stagnation`; a silent approach with approaches left still fails as today (#153).
3. A dependent of a `petitioned` task is `blocked` with cause; petition-only waiting does not
   count as stagnation and triggers adjudication; CONFIRMED skips the task and re-points
   dependents; a cure task inherits the failed task's dependents (#149).
4. An infra-classified instant-exit streak never aborts inside the outage budget; reflect
   retries under the ladder (#151).
5. Only the current wave's petitions are open; adjudications are written back into the file;
   exhaustion petitions land in the current wave's file; the MAC key survives resume via the
   bound directory with the event-log witness as fallback (#150, #152).
6. A repeated unchanged detail request is a 304; iteration rows are cached; the client backs
   off and pauses when hidden (#148).
7. `smoke`/fast/`docker`/`browser` tiers by marker; xdist recipe recorded; flow cases landed
   with the § "Subsumed" table complete and checked; `v0.19-suite-budget.md` records measured
   wall clocks against the targets (G).
8. Version `0.19.0` in both files; roadmap block; the row per the snapshot convention;
   `LAUNCH_SHA` current (H).
9. #148–#154 closed with fresh-`GET`-verified evidence or the cut disclosed; all lanes green at
